# Личный кабинет ВЭШ

Первый рабочий блок на Laravel 13 / Filament 5. Студенческие страницы оформлены по [странице программы ВЭШ](https://veshk.ru/mba-commercial-director). Это прототип для проверки, приёмка владельцем ещё не проведена.

## Что работает

- Отдельный справочник программ: название, обязательный уникальный ТЕГ по регламенту, раздел. ТЕГ вводится вручную, регистр/символы сохраняются, крайние пробелы убираются. Каталог редактирует старший, остальные сотрудники просматривают.
- Группы выбирают программу из справочника и хранят отдельные название, ТЕГ группы, №, тип, статус, администратора, формат, чат, даты запуска/выпуска, срок после выпуска, продление, приветствие, служебный комментарий и отметку заполнения. Доступны карточка, редактирование и переход в ЛК. ТЕГ новой группы автоматически составляется из ТЕГа программы и номера через дефис. Существующие ТЕГи сохраняются при несвязанных изменениях.

- Шаблон страницы задаётся в программе: MBA / длительная, короткая или корпоративная программа. Состав блоков можно настроить. Новая группа получает независимую копию; изменения программы не меняют существующие группы.
- Отдельный редактор страницы ЛК: добавление, удаление, скрытие и перестановка блоков; расписание по месяцам, ЕКБ/МСК, контакты и несколько чатов, подключение, записи по модулям, внешняя папка, текст, видео и Holst. Главный экран, FAQ и подвал остаются общими.
- Самостоятельная регистрация: ФИО, уникальная почта, пароль, группа с открытым приёмом или обращение без группы.
- Ожидание проверки, одобрение/отклонение/назначение группы, повторное обучение в существующем аккаунте.
- Администратор изменяет свои группы, чужие видит только для чтения. Старший управляет всеми группами. Серверные policies проверяют права независимо от интерфейса.
- Несколько ответственных за обращения без группы: дополнительная функция для обычных и старших администраторов. В прототипе назначает старший.
- Галочка письма при одобрении: сохраняется защищённый предпросмотр письма; реальной отправки нет.
- Страница группы с разделами, отдельными расписанием и материалами. Закрыты прямые запросы к материалам без доступа.
- Общий срок после выпуска (по умолчанию 30 дней) и отдельная дата продления всей группы. Более поздний личный срок сохраняется; интерфейс индивидуального продления ещё не сделан.

## Локальный запуск

Нужны PHP 8.4 с SQLite и обычными расширениями Laravel, Composer 2. Node.js для текущих страниц не требуется. Версии зависимостей зафиксированы в `composer.lock`.

В каталоге приложения, для **новой локальной копии**:

```sh
composer install
cp .env.example .env
php artisan key:generate
php -r "file_exists('database/database.sqlite') || touch('database/database.sqlite');"
php artisan migrate
php artisan db:seed
```

Для деморежима установите `DEMO_MODE=true` в локальном `.env`, затем:

```sh
composer run dev
```

Открыть `http://127.0.0.1:8085/demo`. Можно выбрать слушателя, ожидающего одобрения, обычного и старшего администратора. При обычном входе демонстрационные адреса: `student@vesh.test`, `waiting@vesh.test`, `admin@vesh.test`, `senior@vesh.test`; пароль тестовых аккаунтов — `VeshDemo2026!`. Это только вымышленные локальные учётные записи. Seeder и вход по деморолям запрещены в production; `DEMO_MODE` в примере настроек выключен.

Новые миграции сохраняют существующие группы, слушателей и учебное наполнение. У старых групп программу нужно выбрать при следующем редактировании. Demo-seeder использует учебные теги ДЕМО_КД, ДЕМО_EXCEL, ДЕМО_МЕН, без импорта реальных данных Airtable.

В существующей установке не перезаписывайте `.env`, ключ и базу. `migrate` обновляет схему без сброса данных. Не используйте `migrate:fresh` на рабочих данных.

## Проверка

```sh
php artisan test --compact
php vendor/bin/pint --dirty --format agent
composer validate --no-check-publish
```

Проверено 02.11.2026: **40 тестов, 238 проверок**. Проверки включают регистрацию, повторы, открытый приём заявок, неизвестную группу, границы административных прав, защищённые файлы, письмо с галочкой/без, сроки и отключение демовхода в production. Добавлены проверки программ/тегов, сохранения новых полей группы, прав на каталог, приватности комментария и сочетания общего/личного продления. Также проверены независимость шаблонов, генерация и уникальность ТЕГа группы, права редактора, порядок/скрытие блоков, безопасные ссылки и сохранение прежних расписаний. База тестов — SQLite в памяти, рабочая база не сбрасывается.

## Границы прототипа

Статус группы пока учётный: доступ определяется сроком, статус не переключается автоматически. Программа содержит раздел, базовый шаблон и собственный набор блоков. Детальные варианты курсовой работы и другие специальные блоки остаются следующими этапами.

Ещё не реализованы: импорт и синхронизация расписания из Google Таблиц/Excel, импорт студентов, ручное создание/зачисление, доставка писем, восстановление и подтверждение почты, публичная ссылка группы, журнал посещений, панель преподавателя, интеграции Airtable/Enkod, загрузка настоящих файлов. Расписание заполняется в редакторе вручную. Поле источника открывает внешнюю таблицу; оно не импортирует её строки. Данные примеров вымышленные.

Рабочие решения для проверки: срок заканчивается в конце дня по Екатеринбургу; личное продление берёт более позднюю дату относительно общего срока; назначение ответственных и создание групп доступны старшему. Это технические решения прототипа, не отдельное согласование всех деталей процесса.

GitHub Pages размещает только открытую статическую демоверсию интерфейса. Для этой серверной части требуется PHP-хостинг с корнем сайта в `public/`, закрытой базой, собственным `APP_KEY`, HTTPS, `APP_ENV=production`, `APP_DEBUG=false`, `DEMO_MODE=false`. Перед рабочим запуском нужно подключить доставку писем/восстановление доступа, заменить демонстрационные данные, настроить резервные копии и провести приёмку.
